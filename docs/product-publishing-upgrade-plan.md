# 闲鱼商家商品发布与交易后运营改造方案

> 调研与代码盘点日期：2026-09-13

## 1. 结论

当前工程已经具备商品发布、图片上传、自动评价、确认收货后消息、自动擦亮等基础能力，但商品发布模型过于简化，导致页面上虽然出现了“分类”和“交付方式”，实际发布时仍然由平台推荐类目，交付方式也没有进入发布请求。推广模块目前只是本地资源刷新和内部佣金结算，不等于闲鱼平台的商城/集市推广。

建议将改造拆成三层：

1. **P0：发布正确性**——可选择类目、类目属性、价格/SKU/库存、成色、运费与交付方式、服务承诺，并让发布前预检展示最终真实请求。
2. **P1：内容和交易后运营**——图片模板/字体、视频能力探测、草稿、收货后小红花邀请、卖家自动评价、失败重试和状态看板。
3. **P2：平台营销能力**——按账号和商品查询资格，再接入闲鱼集市报名、加速、闲鱼币抵扣、粉丝价等开放能力；不把“推广”做成无依据的开关。

## 2. 闲鱼商品上架目标流程

建议后台按以下 8 步重构：

1. **账号与商品类型**：选择闲鱼账号；选择普通商品/服务或账号实际获权的行业商品类型。
2. **类目与属性**：平台推荐 3 个候选类目，操作人必须确认，也可以展开类目树手动选择；根据类目动态加载品牌、型号、规格等结构化属性。
3. **商品内容**：标题、卖点、详情、使用/交付说明、售后说明；支持素材模板和 AI 辅助生成，但提交前必须人工预览。
4. **图片与视频**：最多 9 张最终商品图、封面排序、裁切和尺寸检查；视频仅在当前账号和发布接口实际支持时显示。
5. **价格与库存**：售价、原价、库存、商家编码；类目支持时配置多规格 SKU 与各 SKU 价格/库存。
6. **交易与物流**：线上交易/当面交易、包邮/固定运费/运费模板/自提、发货地；软件或卡券使用账号实际获权的虚拟交付链路，不用实物运费字段冒充。
7. **服务与售后**：仅展示平台返回且账号可签约的服务承诺，例如发货时效、退货保障；同时配置发货内容、售后群引导与确认收货后的评价邀请。
8. **预检与发布**：保存草稿、发布前校验、展示最终类目/价格/运费/服务/SKU/媒体摘要，确认后提交；按请求 ID 幂等，记录平台商品 ID 和完整回执。

## 3. 当前工程与目标的差距

| 能力 | 当前情况 | 改造要求 |
| --- | --- | --- |
| 类目 | 调用平台推荐后直接取第一个；页面“素材分类”不进入发布请求 | 增加候选类目、类目树、手动确认、类目属性和账号类目权限校验 |
| 价格 | 只有单一售价 | 增加原价、SKU 价格、库存、商家编码、价格力提示 |
| 描述 | 纯文本标题和详情 | 增加结构化模板、分段预览、敏感/矛盾信息校验；不要向平台提交 HTML 字体 |
| 图片 | 支持 1–9 张和排序 | 增加尺寸、比例、清晰度、二维码/联系方式风险检测和封面模板 |
| 字体 | 平台描述字段没有字体模型 | 把字体实现为“图片海报模板”的视觉能力，字体授权、字号、颜色只作用于生成图片 |
| 视频 | 本地上传组件可以接收媒体，但商品发布只构造图片记录 | 增加账号/接口能力探测；支持时转码、上传、封面和回执校验，不支持时明确提示去 App 补充 |
| 运费/包邮 | 发布请求固定为不包邮、不支持运费、不自提，页面交付方式未生效 | 增加包邮、固定运费、运费模板、自提及发货地，按商品类型映射真实平台字段 |
| 服务保障 | 四项服务承诺全部固定关闭 | 从平台读取可选服务及协议内容，用户确认后再开启，保存签约版本和时间 |
| 草稿/预约 | 商品发布页只有预检与立即发布 | 增加草稿、复制、定时任务；最终发布前再次预检 |
| 自动评价 | 已有关闭/总是/买家先评后评三种模式和文案池 | 补充订单级执行记录、失败原因、人工重试、评价真实性提示 |
| 小红花邀请 | 已有确认收货后最多 5 条消息，买家已评价会停止 | 增加预设、一键启用、安静时段、每单只发一次和消息效果统计；默认关闭 |
| 评价回复/追评 | 尚无完整的买家评价内容分流和人工审核队列 | 先查询订单评价；普通评价可生成回复草稿，负面评价和争议只进人工队列 |
| 商城/集市推广 | `REFRESH_PROMOTION` 只刷新本地账号状态 | 新建平台营销适配器，接入资格、计划、报名、取消、续期、状态和效果查询 |
| 佣金 | 当前 `commissionAmount` 是内部货源分销结算金额 | 与平台佣金严格分表分名；平台侧只使用计划返回的允许范围或值 |
| 曝光 | 只有自动擦亮等操作，没有归因数据 | 增加曝光/想要/咨询/成交漏斗；不承诺曝光量，不做刷量、虚假互动或高频重发 |

## 4. 数据与接口设计

### 4.1 商品发布模型

新增 `MerchantListingDraft`（或将现有 MATERIAL/PUBLISH_RULE 明确拆分）：

- 基本信息：`accountId`、`listingType`、`title`、`description`、`merchantCode`
- 类目：`categoryId`、`categoryPath`、`channelCategoryId`、`categorySource`、`categoryConfirmed`
- 属性：`properties[]`，每项包含平台属性 ID、值 ID、展示文本和必填标记
- 媒体：`images[]`、`video`、`coverIndex`、媒体平台文件 ID、上传状态
- 价格库存：`price`、`originalPrice`、`stock`、`skus[]`
- 交易物流：`tradeType`、`shippingMode`、`shippingFee`、`shippingTemplateId`、`selfPickup`、`shipLocation`
- 服务：`serviceProtocols[]`，包含服务代码、是否开启、协议版本和签约时间
- 运营：`postReceiptAutomation`、`promotionPlan`
- 发布审计：`requestId`、`payloadSnapshot`、`platformItemId`、`platformResponse`、`status`

### 4.2 后端服务拆分

- `CategoryCapabilityService`：类目推荐、类目树、属性、账号可用类目。
- `ListingMediaService`：图片/视频检测、上传、平台文件 ID 与封面。
- `ShippingCapabilityService`：按账号、类目和商品类型读取可用交付/运费方式。
- `ListingPublishService`：把草稿转换为平台请求，做幂等提交和回执确认。
- `PostTradeEngagementService`：卖家评价、买家评价查询、小红花邀请、人工任务。
- `MarketplacePromotionService`：集市计划、资格、报名、取消、续期、效果；无权限时返回明确的 `UNAVAILABLE`，不得伪造成功。

### 4.3 API 建议

- `GET /api/merchant/listing-capabilities?accountId=...`
- `POST /api/merchant/categories/recommend`
- `GET /api/merchant/categories/tree`
- `GET /api/merchant/categories/{id}/properties`
- `POST /api/merchant/listing-drafts`
- `PUT /api/merchant/listing-drafts/{id}`
- `POST /api/merchant/listing-drafts/{id}/preflight`
- `POST /api/merchant/listing-drafts/{id}/publish`
- `GET /api/merchant/promotions/eligibility?accountId=...&itemId=...`
- `GET /api/merchant/promotions/plans?accountId=...&itemId=...`
- `POST /api/merchant/promotions/enroll`
- `GET /api/merchant/promotions/enrollments/{id}`

## 5. 交易完成后的自动化设计

### 卖家自动评价

保留当前三种模式，但增加以下约束：

- 以 `accountId + orderId + rateType` 建立唯一键，防止网络重试重复评价。
- 提交前再次读取平台订单与评价状态；只在平台允许评价/追评时执行。
- 文案池随机不等于真实性，应按商品和履约结果选择模板；异常订单不自动好评。
- 记录平台回执、失败原因和下次重试时间，连续失败转人工。

### 邀请小红花/请求买家评价

- 触发条件：平台确认交易完成、无退款/争议、买家尚未评价。
- 默认每单只发送 1 条，建议在确认收货后延迟 10–30 分钟；可设安静时段。
- 文案保持中性，例如“感谢支持；如果本次体验符合预期，欢迎留下真实评价或点亮小红花”。
- 买家已评价、已退款、发起争议、已发送或账号离线时立即停止。
- 不提供返现、赠品换好评，也不只索要正面评价。

### 自动评论/评价回复

- 先把买家评价拉回后台并分类：正向、一般、负向、售后风险。
- 正向评价生成可编辑的回复草稿；一般/负向/含退款关键词的一律人工确认。
- 只有确认平台接口支持该种“回复/追评”且订单仍在窗口内，才展示发送按钮。

## 6. 商城推广、曝光与佣金

平台营销应做成独立生命周期，不能塞入商品发布请求：

1. 查询账号是否有集市/活动能力。
2. 查询商品是否可报名以及允许的价格、库存、周期、是否可加速、佣金范围。
3. 由用户确认费用、库存占用、周期和活动规则。
4. 提交报名并轮询/接收审核状态；失败展示平台原始原因。
5. 跟踪曝光、想要、咨询、支付、退款和净收益，按商品/账号做前后对比。
6. 到期前提示续期；仅在平台支持且用户明确开启时自动续期。

“佣金”需拆为三个不同概念：

- `platformPromotionCommissionRate`：平台活动或联盟计划佣金比例；受计划与资格约束。
- `platformServiceFee`：平台交易/服务费用，只读记录。
- `internalDistributionCommissionAmount`：当前工程的内部货源分销结算金额。

三者不可共用当前 `commissionAmount`，否则财务和报名逻辑都会出错。

## 7. 实施顺序与验收

### P0：发布正确性

- 完成类目选择与确认、结构化属性、原价/SKU/成色、运费与交付、服务协议。
- 修正标题长度等前后端校验，使其以所用平台接口的真实限制为准。
- 预检返回最终 payload 摘要，而不是只返回推荐类目和地址。
- 单元测试覆盖所有字段映射；契约测试保存匿名化请求/响应样本。

**验收**：在一个测试账号上分别用普通实物和当前软件商品做草稿及预检；页面摘要与平台最终详情逐字段一致，重复提交不会产生第二个商品。

### P1：内容和交易后运营

- 完成图片模板/字体、视频能力探测、草稿复制和发布状态页。
- 把已有小红花邀请配置从“自动发货深层设置”提到商品运营页，增加预设和一键启用。
- 补充自动评价执行记录、失败重试、订单级开关和人工异常队列。

**验收**：模拟交易完成、买家已评价、退款、重复回调、网络超时五类场景；任何订单最多发送一次邀请、最多提交一次主评价。

### P2：营销闭环

- 完成营销能力适配器和账号/商品资格页。
- 有开放能力时接入集市计划查询、报名/取消/续期/状态；无能力时只给出平台 App 的人工路径。
- 建立曝光到成交漏斗和净收益计算。

**验收**：没有资格的商品不可提交；报名状态以平台查询结果为准；佣金与内部结算金额分离；系统不显示无法验证的“曝光成功”。

## 8. 关键风险与原则

- 当前发布使用网页 MTop 接口，平台字段可能变化；应保留能力探测、特性开关、回执快照和单账号灰度。
- 官方服务商 API 存在授权和部署条件，营销能力尤其不能假设所有账号都能使用。
- 商品说明必须与真实交付一致；软件插件的类目、授权、售后、有效期和交付方式应由平台可用类目及实际资质决定。
- 平台排名由价格、活跃度、信用、服务水平、合规、用户偏好和竞争力等多因素共同决定，产品只做运营辅助和效果归因，不承诺或伪造曝光。
- 评价必须真实、与交易相关；邀请评价应中性，不做刷评、返现换好评或只引导正面评价。

## 9. 外部依据

- 淘宝开放平台“闲鱼电商 SAAS”目录：类目树、类目预测、属性、描述生成、发货方式、订单评价查询等能力。
- 淘宝开放平台商品发布文档：商品图片最多 9 张，并包含售价、原价、邮费、成色、类目、交易方式、结构化属性、SKU 等字段。
- 淘宝开放平台订单评价与追评文档：服务商可在授权场景中创建评价/追评。
- 淘宝开放平台闲鱼集市相关文档：存在计划查询、报名记录、单商品操作、报名周期、价格、库存和加速等字段，但需要授权且部分要求聚石塔内调用。
- 《闲鱼社区卖家服务协议》：允许以文字、图片、视频发布商品；推广资格与效果受活动定位、商品竞争力、综合排名和合规等因素影响；不得以不正当方式提升信用。
