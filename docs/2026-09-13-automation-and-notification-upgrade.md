# 2026-09-13 自动化可靠性与通知改进

## 通知分类

| 事件 | 原有渠道 | 改进后的含义与操作 |
| --- | --- | --- |
| ORDER_CREATED 新订单 | 通知中心（含企业微信） | 发现订单，不代表发货失败，不提示直接重复手工发货 |
| DELIVERY_SUCCESS 交付成功 | 通知中心 | 内容交付完成；平台确认与买家收货另看时间线 |
| DELIVERY_EXCEPTION 交付异常 | 通知中心、邮件 | 区分内容交付、私聊回执、平台确认；结果未知先核对再补发 |
| ACCOUNT_OFFLINE 账号掉线 | 通知中心、邮件 | 提示业务影响和退避重连，普通网络抖动不直接要求扫码 |
| CREDENTIAL_EXPIRED 凭证失效 | 通知中心、邮件 | 自动恢复失败后发送对应账号续期二维码 |
| KAMI_STOCK_LOW 库存预警 | 通知中心、邮件 | 提示补货；库存耗尽原本另有邮件入口 |
| ACCOUNT_VERIFICATION_REQUIRED 官方安全验证 | 原为邮件专用，新增通知中心 | 与 Cookie 过期分开；要求官方验证，不声称二维码可绕过验证 |
| ACCOUNT_RECOVERED 账号恢复 | 新增通知中心、邮件 | 保存凭证并确认消息连接恢复后发送 |

原有邮件还包括 SMTP 测试、库存耗尽通知。通知中心继续使用数据库 Outbox 重试；SMTP 仍为同步投递（原有普通邮件入口异步调用），并未声称已改造成持久化邮件队列。

企业微信凭证失效订阅自动涵盖本次续期二维码、相关恢复和安全验证提示，不要求重新勾选。其他通知渠道保留文字通知，本次仅企业微信实现直接图片投递；邮件使用 CID 内嵌图片，不依赖公网图床。

## 通知内扫码续期

1. 仅对启用且确认凭证失效、自动恢复失败的账号触发；不会因为一次网络掉线就创建二维码。
2. 生成绑定目标账号和租户的登录会话，企业微信收到说明和图片，邮箱收到内嵌图片。图片直接注明账号 ID、账号备注与北京时间最晚扫码时间；备注自动换行，空备注显示“未填写备注”，不覆盖二维码和留白区域。运行镜像安装中文字体，避免中文变成方框。
3. 使用对应闲鱼账号扫码并确认。扫码账号与目标账号不符时拒绝更新，不新增其他账号、不覆盖原账号。
4. 后台轮询二维码会话；凭证保存完成才报告扫码确认成功，随后重新建立消息连接。
5. 只有连接状态确认成功，才发“已恢复”。凭证保存但连接未恢复，会发不同提示。
6. 安全待处理队列按既有规则恢复；已发送但回执未知、需人工核对的订单和回复不会自动重发。不会重放历史已完成订单。

2026-09-13 根据使用反馈延长等待：取消通知四分钟提前换码，本地会话监控上限改为二维码生成完成后的十五分钟，生成接口返回统一截止时间，通知不再自行推算更短的有效期。此时间仅是本系统等待上限，**不是平台对单张二维码有效十五分钟的保证**；平台返回过期立即按过期处理。

每轮自动续码窗口三十分钟，最多十张；只有本张过期才换码，以最新图片为准，窗口末尾新图片的最晚扫码时间不会超过该轮截止时间。已扫码等待手机确认时不会主动换码或提前终止流程，仍受平台状态和会话监控上限约束。达到窗口或张数上限后停止刷屏；持续失效每六小时开始下一轮。错扫、取消或额外安全验证会停止当前轮。需要立即恢复且错过窗口时，仍可在后台生成新码；本次未增加公网免登录刷新链接或企业微信回调入口。

二维码不写入数据库、不出现在日志和公开 URL；Outbox 仅保存短期引用。失效、恢复或进程重启后旧图片不再发送。邮件二维码失败最多尝试三次且不超过图片有效期。二维码会话和邮件重试状态是内存态：重启后需要新会话，不保证原二维码继续有效。只应投递到可信运维群和私有邮箱，勿转发。

## AI 与交付可靠性

- 修复相同消息重放先取消待回复任务、再被数据库去重的顺序问题。
- 工作线程开始执行时才领取 AI 任务；发送前复查账号状态和人工接管，持久化外发标志并校验领取令牌。
- 未发送前的准备失败有限重试；发送超时、发送后连接中断不再当成成功，也不会直接自动重发。
- 订单自动发货、自定义发货及私聊发送前核对平台订单买家，禁止错买家、自发货、退款/关闭订单交付。
- 交付任务使用独立调度线程续租和每次领取的令牌；外发后进程中断进入人工核对。
- 私聊未确认送达不再提前标记完整交付；配置的图片交付也等待回执。
- 平台确认发货采用独立数据库任务，有限重试，支持只重试确认，不重新分配卡密。
- 商品真实 SKU ID 优先；文本映射有歧义时不猜规格，增加同步和本地别名。
- 订单时间线展示下单、付款、内容、私聊、平台确认、交易及评价状态。低频对账更新状态，不通过迁移补发历史订单。
- 增加按租户/账号/商品/买家一次性欢迎语（文字、图片）及议价底价检查。欢迎语默认关闭，不替代已启用 AI/关键词的正常回答。底价检查是规则防护，不是对任意自然语言承诺的形式化保证，也不实际改平台价格。
- Token 按到期时间提前错峰刷新，失败退避，额外安全验证时停止自动续期；更新失败尽量保留仍可用连接。

## 升级与验证

扫码状态轮询使用独立线程池（最多 64 个并发轮询、无排队），保留租户上下文，不占用 AI/交付业务线程；适配二三十个账号集中续期。超过容量会拒绝创建可用通知，不将过期二维码排在长队中。

部署复查补充了两项兼容处理：平台确认队列使用订单号字节比较，兼容历史表排序规则差异；通知终态保留非空时间值，避免旧表 `next_retry_time NOT NULL` 导致失败任务无法结算。

迁移版本 V24，仅增加字段和三张业务表，不给历史订单批量创建交付/确认任务。保留原租户隔离、共享资源、浏览器配置、RAG、卡密库存与凭证/私聊双渠道能力。

自动化测试覆盖消息重放、买家核验、过期租约拒绝外发、SKU 歧义、底价保护、错扫码拒绝更新、二维码有效期/租户隔离、企业微信图片请求、通知失败重试和确认连接后才报告恢复。另以 `scripts/verify-v24-isolated.sql` 验证 MySQL 5.7 真实状态更新；该脚本强制限定测试库名称，使用虚构数据并回滚事务。

发布前须通过：前端类型检查和构建、后端测试、隔离库 Flyway 启动及状态机断言、生产数据库备份、部署后健康与错误日志检查。真实平台扫码、真实收件箱显示、真实买家询问和支付订单仍需运营验收，不能用模拟测试替代。

没有引入代理 IP、改成 Python、合并上游多租户不兼容迁移或执行其他仓库安装脚本。公网一键刷新页、持久化 SMTP 队列和维护窗口更新策略留作后续独立需求。

### 本地低空间补丁构建

`deploy/Dockerfile.app-update` 仅适用于 Java 依赖和 Playwright 版本不变的补丁更新：先完整构建前端并执行 `./mvnw package`，将生成的 `xianyusmart-2.0.7.jar` 放入独立构建目录，再以经过验证的现有闲鱼镜像作为 `BASE_IMAGE` 构建。补丁镜像与完整镜像均安装 `fonts-wqy-microhei`，支持二维码中文备注；除此之外复用已有浏览器和运行环境，避免每个小补丁重复占用近 1 GB 浏览器层。Java/浏览器依赖升级必须使用根目录完整 Dockerfile。
